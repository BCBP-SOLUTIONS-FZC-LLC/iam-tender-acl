# iam-tender-acl — Claude Code guide

## What this repo is

`iam-tender-acl` is the **interim** service for the restricted-tender access overlay
(`tender_acl_entries`), extracted from `iam-org-membership` per ADR-0007 Wave 3. It is
**deliberately minimal and disposable** — scheduled to merge into the Tender Service once it
matures (Option D / Wave 4, LLD §22). Do not add long-term abstractions here; every abstraction
that exists (e.g. the swappable `membershipcheck` interface) exists only to let this service run
standalone cheaply, not to anticipate future features.

It owns exactly **one table** (`tender_acl_entries`) and exposes **four endpoints**:

| ID | Method & path | Notes |
|---|---|---|
| TAC-1 | `GET /api/v1/tenants/:id/tenders/:tender_id/acl` | List, admin-gated, not cached |
| TAC-2 | `POST /api/v1/tenants/:id/tenders/:tender_id/acl` | Grant — blocks on a synchronous membership check |
| TAC-3 | `DELETE /api/v1/tenants/:id/tenders/:tender_id/acl/:user_id` | Revoke (soft-delete), optimistic-locked on `record_version` |
| TAC-4 | `GET /internal/tenants/:id/tenders/:tender_id/acl/:user_id` | Mesh-only auth check, Valkey-cached 30s, never 404 |

It has **one synchronous outbound dependency** (a grant-time-only membership-existence check
against `iam-org-membership`, TAC-2 only) and **two inbound async subscriptions** — no outbound
events, ever:

- `TenantOffboarded` → cascade-**delete** all of a tenant's ACL rows (`OffboardingConsumer`)
- `TenantMembershipRemoved` → cascade-**soft-delete** one user's ACL rows in that tenant
  (`MemberRemovalConsumer`, ADR-0007 Wave 3 Phase 3)

Unlike its two ADR-0007 siblings (`iam-catalog-admin`, `iam-group-mapping`), this service **is** on
a live authorization-decision path (TAC-4, the I-12 successor) — its cache and latency posture get
hot-path rigor despite the table's otherwise low write volume.

See [[project_adr0007_decomposition]] for the wave-level decomposition status.

automatically on every `git commit`.

## Package layout

Clean Architecture / Ports-and-Adapters — same layering `iam-group-mapping`/`iam-catalog-admin`
use. This service originally shipped with a flat, unlayered structure (LLD §6, decision TAC-D1,
since **superseded**) — see `ARCHITECTURE.md`'s "Layer model" section for that history.

```
api/                                    AsyncAPI 3.0 spec + api/embed.go (//go:embed asyncapi.yaml)
cmd/tender-acl/                         composition root: main.go, config.go, observability.go
docs/
  lld/iam-lld-tender-acl-service.md     the authoritative LLD (revision-history-tracked)
  swagger/                              generated by `make swag` (swaggo/swag)
  architecture/mermaid/                 diagram sources backing ARCHITECTURE.md
internal/
  core/
    domain/                             TenderACLLevel, TenderACLEntry, CachedAccess, Error — no deps
    port/                               TenderACLRepository, MembershipCheckClient, Cache interfaces
    service/                            ACLService (TAC-1..TAC-4 business logic)
  adapter/
    inbound/
      http/                             Handler, Router, health/readyz, swagger + asyncapi doc routes
      consumer/                         OffboardingConsumer, MemberRemovalConsumer, ProcessedEvents
    outbound/
      postgres/                         TenderACLRepository impl, migrations/, migrate.go
      valkey/                           Cache impl (tac:acl:* keys)
      membershipcheck/                  MembershipCheckClient impl (HTTP call to iam-org-membership)
      metrics/                          business-only Prometheus metrics (see operations.md)
migrations/ → internal/adapter/outbound/postgres/migrations/  0001..0005, up/down pairs
```

## Dependency rules (`.go-arch-lint.yml`)

`domain` (no internal deps) ← `port` (may depend on `domain`) ← `service` (domain + port) ←
`adapters_inbound`/`adapters_outbound` (service/port/domain/observability, or port/domain only for
outbound) ← `cmd` (wires everything). `observability` (`internal/adapter/outbound/metrics`) is
cross-cutting — imported by both inbound HTTP and inbound consumer adapters, not purely an outbound
concern (metrics span both). `docs_swagger` (`docs/swagger`) is generated-only, no internal deps.
Enforced via `make lint`'s `go-arch-lint check`.

## Key files to know

- `cmd/tender-acl/main.go` — composition root: builds `pgcommon.Pool` (main + raw), Valkey client,
  `membershipcheck` HTTP client, two SQS consumers (queue #1 via `platform-events/pkg/config`,
  queue #2 hand-rolled), wires `errgroup` for HTTP server + metrics server + both consumers + 2
  cleanup tickers + graceful shutdown.
- `cmd/tender-acl/config.go` — env var loading (`getEnv`/`getEnvInt`); `SQSQueueURL` deliberately
  removed from here (moved into `sqsEnv.Validate()` via `platform-events/pkg/config`).
- `internal/core/service/acl_service.go` — `ACLService.{List,Grant,Revoke,CheckAccess}`; the only
  place that decides fail-closed-on-membership-check-error and cache invalidation-after-commit.
- `internal/core/domain/acl.go` — `TenderACLEntry.IsActive(now)` (TAE-3: `deleted_at IS NULL AND
  (expires_at IS NULL OR expires_at > now())`), `CachedAccess`.
- `internal/core/domain/errors.go` — the flat error-code taxonomy (`domain.Error{Code, Message}`,
  `domain.CodeOf`) matching the LLD's Appendix: Error Taxonomy verbatim.
- `internal/adapter/outbound/postgres/repository.go` — `withTenant` → `pgcommon.WithValidatedGUCSet`;
  `wrapConnErr` classifies connectivity failures as `dependency_unavailable`.
- `internal/adapter/inbound/http/router.go` — route registration incl. `registerDocsRoutes`
  (`/swagger/*any`, `/asyncapi`, `/asyncapi.yaml`), all gated by `DocsConfig`.
- `internal/adapter/inbound/http/asyncapi.go` — server-rendered AsyncAPI HTML viewer, ported from
  `iam-user-profile`, backed by `api/embed.go`'s compile-time-embedded spec.
- `internal/adapter/inbound/consumer/{offboarding,member_removal}_consumer.go` — the two cascade
  consumers, each idempotency-gated via `ProcessedEvents` (composite key `(event_id, consumer)`).
- `docs/lld/iam-lld-tender-acl-service.md` — the LLD copied into this repo; **update its revision
  history table** (not just the body) whenever a design-affecting change lands here.
